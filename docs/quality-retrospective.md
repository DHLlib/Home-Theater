> 范围：执行 `git fetch --all` 后的全部本地分支与远程分支，截至提交 `468ca65`。`master`、`home-theater-v2-postgresql-version` 及两个远程对应分支当时均指向该提交；归档分支 `origin/home-theater-v1.2-sqlite-version` 为 `fccff7a`。
>
> 方法：遍历 `git log --all`、提交说明、文件列表与关键 diff；用 stable patch-id 识别完全相同的补丁。统计是提交级，不等同于独立 Bug 数或工时。

结论不是“Bug 太多”，而是：**修复速度很快，但大多数修复没有转化为可执行防回归资产；相同事故族因此反复支付定位与返工成本。**

## 2. 主要事故链

### 2.1 聚合与分页：局部修复反复替代整体不变量

关键时间线：

- `0188b94`（6 月 12 日）引入聚合中间表；`a4acf07`（6 月 24 日）已经发现 `videos.py` 与 `aggregator.py` 的重复实现并抽取公共函数。
- `e37110a`（6 月 19 日）把 offset 改为按放大扫描窗口步进，解决跨页重复；`3ac8715`（11 月 8 日）又改回按输出条数步进，因为前一次修复造成翻页跳空。两次方向相反，各自都只证明了症状的一部分。
- `724a156`（10 月 12 日）清理过 100,637 条重复记录；`9bd4684`（11 月 14 日）又处理约 11.7 万组重复，发现 year 回填顺序、跨进程重建和唯一约束缺失。
- `b1cc81a`（11 月 15 日）把增量写入改为 upsert；`e5462cd`（11 月 16 日）处理 2,648 个无来源聚合行导致的跨页重复；`bb76bf2` 同日又统一全量与增量的归一化 key。

共同根因：没有先把“唯一键、来源关系、计数、跨页完整性”写成可执行不变量。每次修一个可见症状，下一层数据假设再暴露。数据清理只能消除当时的脏数据，不能阻止写入路径再次制造它。

### 2.2 下载：并发资源、状态与生命周期没有统一模型

从 `39b39af` 的 Range 下载、`251ab74` 的批量提交、`43c5f63` 的 SSE，到 `59c30b0` 中大量暂停/删除修复，再到 `dda0969`、`2fce045`、`52be539`、`ae880c6`，重复出现：

- 共享 `AsyncSession` / asyncpg 连接并发操作；
- `refresh` 覆盖未提交字段，读最新后再写仍有 lost update；
- queued 与 running 竞争导致暂停信号丢失；
- 删除目录后 worker 仍写入，共享 client 先于子任务关闭；
- DB 已提交进度但 SSE 未发送，或事件字段不完整。

共同根因：把异步任务当成顺序函数补丁，而没有显式描述状态机、允许的状态转换和取消/清理顺序。后续已有 `backend/scripts/simulate_download.py` 覆盖完整生命周期，这是正确方向；必须成为下载改动的固定门槛，而不是一次性调试脚本。

### 2.3 播放与格式：跨层复制规则，第三方配置凭直觉

- 后缀处理先后出现在详情、播放、下载与前端播放器：`805402f`、`d166389`、`5039b25` 等持续修复“某入口能播、另一入口不能播/不能下”。
- HLS 画质在 `b0e17b0` → `4344e00` → `7509dcd` 同一天连续三次调整，最后才发现需要显式锁定 `currentLevel`。
- `a530d68` 又修正 xgplayer 插件配置键，说明此前配置并未真正进入插件。
- `2fce045` 把未知后缀全部尝试直投，`52be539` 次日因测试恢复不支持格式白名单，是没有 `revert` 前缀的行为反转。

共同根因：同一概念有多份实现，且第三方行为没有通过文档、源码或真实播放验证。后缀样例和插件配置没有形成跨端契约。

### 2.4 前端白屏：只测 happy path，生产与失败路径暴露过晚

`8fa8f85`（封面候选耗尽触发 React #300）、`59fa890`（缺少 ResizeObserver）、`e3befdf`（422 结构化 detail 被 Toast 当 React 子节点）、`61b3a5f`/`775af69`（旧 HTML 引用失效 lazy chunk）都发生在错误、空数据、候选耗尽或旧缓存路径。

共同根因：开发环境与正常接口响应不能覆盖真实失败组合；生产压缩后又缺少 sourcemap，增加定位成本。现有设计规则已经覆盖 hooks、主题和占位组件，仍需用失败路径测试执行，而不是只靠代码审查。

### 2.5 性能与外部资源：先按小数据/理想网络设计，再被动补救

- `c56a0c4` 引入 5,000 行缓存上限，后来发现冷门分类被挤掉；缓存容量目标没有和数据完整性目标一起验证。
- `7047b7e`、`a2aa325`、`818175b` 分别处理 SSLContext 阻塞、每请求 TLS 握手、45 万行取回 Python 统计。
- `ee5deb2` → `14dc968` → `ed812b1` 把失效清理从同步请求逐步改为后台、游标、两轮确认；批量 20 的上限与第三方静默截断也必须靠真实响应确认。
- `5865ec3` 的短词前缀优化仍需 `b614f46` 修回退、`5275179` 才根治任意 2 字子串；索引是否有效取决于实际查询形态与执行计划。

共同根因：把“接口返回成功”误当作语义正确，把小夹具延迟当成生产规模性能。缺真实样本、上限探针、总预算和执行计划。

### 2.6 Windows 启动与发布：环境状态靠记忆，脚本本身缺少语法门

`de0b891` 先把启动脚本改成 CRLF + BOM，`9889cb7` 同日又移除所有非 ASCII；之后还有 `7009ea1`（param 位置/类型表达式）、`aa6c1e4`（npm 启动方式）、`753dcad`（esbuild 临时目录）、`a8222dd`（cmd 包装器）。另有残留进程、双实例写日志导致轮转失败。

共同根因：把平台脚本当作“不需要编译的代码”，并且调试进程没有确定的所有者与清理步骤。现有启动脚本已吸收多项修复；新增自动化应做语法解析和真实启停，不应再靠改编码猜测。

## 4. 六个共同根因

| 根因 | 历史证据 | 当前沉淀 |
|---|---|---|
| 质量依赖人工记忆 | 104 个 fix 仅 5 个带测试；CI 同日增删；本地虚拟环境原先没有 ruff | `scripts/verify.py`、ruff 开发依赖、可选 pre-commit 钩子 |
| 没有先定义不变量 | 分页两次反向修复；聚合重复、孤儿、计数问题连续出现 | `CONTRIBUTING.md` 分页/聚合规则；`audit_aggregated.py` 只读审计及测试 |
| 同一规则多处复制 | HLS 在播放/下载/前端漂移；全量与增量归一化 key 漂移 | 后端 `is_hls_suffix` 单入口；前后端同样例契约测试 |
| 并发只看顺序 happy path | 下载暂停/删除、NOTIFY、聚合写键反复竞态 | 状态转换与取消清理硬规则；保留并强制使用生命周期模拟 |
| 对外部行为与规模做假设 | 第三方批量上限、HLS 配置、SQL 索引、TLS/事件循环 | 真实响应、EXPLAIN、观测先行与后台预算规则 |
| 大提交与知识未闭环 | WIP/合集提交；错题本保留已推翻的 offset 方案 | 单域小提交；后续修复必须纠正旧文档；本报告与长期规则分离 |

最核心的因果链是：

**没有可执行不变量 → 只能靠症状判断修复是否有效 → 修复落在某一条路径或某一种环境 → 其他路径再次暴露 → 再写一条踩坑记录，但没有自动门 → 同类成本重复发生。**

## 5. 本次落地与边界

落地内容：

1. `CONTRIBUTING.md`：长期有效的质量、契约、并发、数据、UI 与提交规则。
2. `scripts/verify.py`：统一静态检查、前端测试、完整 PostgreSQL 验收、生产构建和本地钩子安装。
3. `backend/scripts/audit_aggregated.py`：重复键、孤儿、悬空来源、来源计数、重复来源、空归一化键的只读审计。
4. `backend/app/services/parser.py` 的 `is_hls_suffix`：播放、下载、扩展名共用后端判定；前后端使用相同契约样例。
5. 修正分页错题本中被后续提交推翻的结论，并让首页搜索相关测试显式拒绝 duplicate-key 警告。

不在本次范围内：不改写历史、不清理历史数据库转储、不恢复 CI、不把正常视觉演进算作 Bug，也不借复盘顺手重构整个下载器或把分页改成 keyset。现有工具和规则不能替代真实场景验收；后续仍应按改动域执行完整验证。
