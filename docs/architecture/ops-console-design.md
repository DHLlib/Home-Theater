## 1. 背景与问题

「看板」「采集站管理」「运维任务」是同一个领域的三种视图，目前被拆成三个入口：

| 维度 | 设置-采集站管理 | 设置-运维任务 | 看板 |
|---|---|---|---|
| 站点列表 | 有（名称/地址/启停） | 有（健康/待补全/最近刮削/下次检查） | 有（已收录/补全率/资源占比） |
| 全局操作 | 批量检测、批量嗅探、导入导出 | 全量刮削、全站补全、清理 | 无（头部只有补全） |
| 单站操作 | 增量刮削 | 无 | 单站补全 |
| 补全入口 | — | 有 | 有（重复） |
| 补全进度 | — | 一行摘要 | 完整进度面板（重复） |
| 任务记录 | — | 有 | — |
| 刮削日志 | — | 有 | — |

由此产生四种重复与断点：

1. **三张站点表**：同一批站点在三个页面各有一套字段与排序。
2. **两个全站补全入口、两份补全进度**：看板头部与运维任务操作条都能启动 `detail.fill`。
3. **发起与观测分离**：站点行的「增量」提交的是 `crawl.incremental` 运维任务，但进度与取消在另一个 tab。
4. **探测结果一次性**：采集站管理的批量检测结果只存在组件 state，刷新即丢；而探测日志已写库并在 overview 中可读。

实测当前运维任务页整页高 **4,963px**：近 30 条任务记录中大部分是定时增量，20+ 个站点的状态表与数十行刮削日志全部平铺。信息本身没有错，错在默认全部展开。

**结论**：三者合并为一个「运维」页。**站点是对象，三个全局按钮是动作，看板统计/任务记录/日志是状态与历史**。页面按「概览 → 全局动作 → 站点卡片 → 任务记录 → 刮削日志」组织，默认只展开前三个，历史默认折叠。

## 2. 目标与非目标

**使用者与场景**：个人或家庭维护者，主要在桌面浏览器操作，偶尔用手机；典型时刻是「新增了一个站」「发现某部片缺集」「播放源失效」「想看昨晚的刮削有没有跑完」。此时他需要的是：一眼看出哪几个站有问题 → 发起一次针对性的补全/刮削/清理 → 确认它跑完了。成功标准是**不需要记住三个页面、不需要在表格里找站点、任务永远可见可取消**。

### 2.1 目标

- 一个页面完成「看状态 → 处理 → 看结果」，发起与观测同屏。
- 站点只在一个地方管理：卡片是唯一入口，单站操作全部收进弹层。
- 全局操作只保留一套入口：全量刮削 / 全站补全 / 清除失效资源。
- 保留现有全部能力：站点增删改、启停、导入导出、批量嗅探、批量检测、单站增量/补全/探测、任务取消、刮削日志、7 天趋势。
- 删除重复实现：三张站点表、两个全站补全入口、两份补全进度、设置页的「最近更新」时间戳。

### 2.2 非目标

- 不修改后端任务模型、协调器、调度器与数据库表结构。
- 不新增统计指标；趋势继续使用 `crawler_stats_history`。
- 不做权限、多用户、审计日志。
- 不新增「单站全量刮削」入口（后端支持，但当前产品未暴露，保持现状）。
- 不改分类设置与下载设置。

## 3. 信息架构

### 3.1 导航与路由

| 位置 | 现状 | 之后 |
|---|---|---|
| 桌面顶栏 | 首页 收藏 看板 最近 下载 设置 | 首页 收藏 **运维** 最近 下载 设置 |
| 移动底栏 | 首页 搜索 收藏 下载 我的 | 首页 搜索 收藏 下载 **运维** 我的（6 项） |
| 路由 | `/dashboard` | `/ops`；`/dashboard` → `/ops`（`replace`） |
| 设置页签 | 采集站管理 / 分类设置 / 下载设置 / 运维任务 | 分类设置 / 下载设置（默认 `categories`） |
| 旧深链 | `?tab=sites`、`?tab=logs` | 重定向 `/ops`（`replace`） |

- 导航图标沿用 `DashboardIcon`，不新造图标。
- `/ops` 同时注册在 `router.tsx` 与 `desktop/router.tsx`。
- 设置页不再保留站点入口：导航已有「运维」，避免第二入口。
- 设置页保留 `?tab=categories`、`?tab=download` 深链；无参数或非法值时进入分类设置。
- 移动端实际底栏是「首页/搜索/收藏/下载/我的」5 项（没有看板）；本次新增第 6 项「运维」（2026-11-23 已确认）。

### 3.2 页面结构

```
页头（标题 + 统计时间 + 刷新）
概览条（4 个数字）
7 天趋势（折叠，摘要一行）
全局操作条（3 个按钮 + 清理速度）
活动任务条（仅运行中出现）
采集站（筛选 + 排序 + 卡片墙）
任务记录（折叠）
刮削日志（折叠）
```

顺序理由：从聚合到具体（概览 → 站点），动作紧邻其对象（全局动作在站点之上，单站动作在卡片弹层），历史默认收起（趋势 → 任务 → 日志）。趋势紧跟概览，同属「我有什么」；折叠成一行摘要，不独占分区。

## 5. 组件规格

### 5.0 视觉基线

| 项 | 规格 |
|---|---|
| 页面容器 | 沿用现有 Layout 内容宽度与 20px 边距 |
| 分区间距 | 20px；分区标题 13/600、字距 0.03em、`--text-secondary`（工具页沿用现有紧凑层级，不套内容页 18px 分区标题） |
| 表面 | 卡片与分区用 `--bg-elevated` + 1px `--border`，圆角 12；不叠投影 |
| 浮层 | 抽屉/底部弹层圆角 16（抽屉靠右，仅左侧上下圆角），`--scrim` 遮罩，允许一层软投影；不用 backdrop-filter |
| 主操作 | 白底黑字（`--btn-primary-bg/fg`）；绿色只用于进度、进行中、新增 >0 |
| 数字 | 全部 `font-variant-numeric: tabular-nums`；卡片与表格右对齐 |
| 状态 | 8px 圆点 + 文字 chip，不单靠颜色表意 |
| 动效 | 120/200ms，`cubic-bezier(0.16, 1, 0.3, 1)`；折叠高度动画与抽屉滑入响应 `prefers-reduced-motion` |
| 图标 | 复用 `components/icons.tsx` 与页内现有 SVG，线宽 2，尺寸 14/16 |

与现有 `SiteHealthDrawer` 的三处偏差修正：

1. 遮罩改用 `--scrim`，不再写死 `rgba(0,0,0,0.6)`。
2. 去掉 `backdrop-filter: blur(4px)`（DESIGN.md 禁止装饰性玻璃模糊）。
3. 左侧描边与投影二选一：保留一层软投影，去掉 `borderLeft`。

### 5.1 页头

- 标题「运维」（沿用 `.page-title`），右侧一行元信息：`统计于 HH:mm` + 刷新按钮（40×40，`aria-label="刷新统计"`）。
- 不加副标题、不加操作按钮（全局操作在下方操作条，避免两个主入口）。

### 5.2 概览条

- 一条横向分栏，不是 4 张 KPI 卡：`--bg-elevated` + 1px `--border`，圆角 12，内部分隔线 1px `--border`。
- 四项：已收录 `/crawler/stats.total`、已补全 `with_detail`、未补全 `without_detail`、已聚合 `aggregated_count`。
- 数值 24/600（移动 20/600）；标签 12、`--text-secondary`。
- 未补全 > 0 用 `--danger`，= 0 用 `--text-muted`（状态色只在有值时出现）。
- 加载中：4 条骨架条，不用 spinner。
- 失败：「统计加载失败」+「重试」文字按钮。
- 数据来自 localStorage 60 秒缓存，进入页面先渲染缓存再后台刷新；手动刷新按钮立即拉取并更新缓存。

### 5.3 全局操作条

| 按钮 | 样式 | 说明 |
|---|---|---|
| 全站补全 videolist | 白底主操作 | 最高频、可重复、无破坏性；点击直接提交，无确认 |
| 全量刮削 | 描边 | 长任务（20–40 分钟），保留确认弹窗 |
| 清除失效资源 | 红描边 | 破坏性，保留确认弹窗；右侧挂「清理速度」下拉（省流/标准/快速） |
| 清理速度 | 紧凑下拉 | 值持久化在 `ht-cleanup-speed`；清理运行中禁用 |

- 状态：同类任务活动时按钮禁用并改文案（`全站补全中…` / `全量刮削中…` / `清理进行中…`），`startingKind` 期间显示「启动中...」。
- 跨类冲突交给协调器：启动返回 `skipped`/`deduplicated` 时沿用 `useMaintenance` 的 toast，不自行加锁。
- 站点数为 0 时三个按钮全部禁用，`title="请先添加采集站"`。
- 移动端：主操作独占一行，次操作两列；清理速度在清理按钮下方一行。
- 保留 `?cleanup_dry_run=1` 的干跑开关（现有验证链路）。

### 5.4 活动任务条

- 仅当存在 `queued/running` 任务时出现，位于全局操作条与卡片墙之间。
- 每行：`任务类型 · 站点名` + `完成 / 总数` + 4px 进度轨 + 取消按钮；最多 2 行，超出显示「+N 个任务」。
- 点击行（非取消按钮）展开任务记录并滚动定位；取消沿用现有确认文案。
- `aria-live="polite"`，只在任务状态变化时播报，不逐 tick 播报。
- 折叠的任务记录不承担唯一的进度可见性——这条是硬要求。

### 5.5 采集站卡片墙

#### 5.5.1 卡片解剖

```
● 站点名                        健康 chip
待补全 N / 总数                  补全率 %
────────────────────────────── 4px 进度轨
最近 22:22 · 下次 22:28
```

- 第一行：8px 状态点（`--success` / `--danger` / `--text-muted`）+ 站点名 14/500 + 右侧健康 chip（正常 105ms / 异常 / 未探测 / 已禁用）。健康 chip 用状态色 12% 底 + 状态色文字；已禁用用 tint 底 + 描边。
- 第二行：`待补全 N / 总数`（12，数字右对齐、tabular）；右侧 `补全率 %`，`without_detail=0` 用 `--text-muted`，>0 用 `--danger`。
- 第三行：4px 轨道（`--tint-soft`）+ `--primary` 填充，宽度为补全率；`aria-hidden`，数值已在文本中。
- 第四行：默认 `最近 HH:mm · 下次 HH:mm`（跨天补 `MM-DD`；已过则显示「待检查」）；本站有活动任务时改为 `任务中 · 增量刮削 1/1`（健康 chip 仍在第一行）。
- 已禁用：健康 chip 显示「已禁用」，状态点转 `--text-muted`；文字不使用透明度（避免对比度下降），排序沉底。
- 站点无数据：`待补全 0 / 0`、补全率「—」、`无刮削记录`。
- 自动禁用：卡片只显示「已禁用」，`auto_disabled_at` 在弹层内提示。

#### 5.5.2 排序

默认「需关注优先」，按桶排序，桶内再按规则：

| 桶 | 条件 | 桶内排序 |
|---|---|---|
| 0 | 本站有活动任务（`site_id === 站点` 的任务） | 开始时间升序 |
| 1 | 健康异常（`last_probe_ok === false` 或 `last_check_status` 异常） | 连续失败次数降序，最近探测时间升序 |
| 2 | 无刮削记录（`last_crawl_at == null` 且有数据 / 新站） | 站点 id 降序（新站在前） |
| 3 | 待补全 > 0 | 补全率升序，待补全数降序 |
| 4 | 正常 | 名称 |
| 5 | 已禁用 | 名称 |

> 判定优先级：桶 0 → 桶 5（已禁用直接沉底，不参与异常/待补全排序）→ 桶 1 → 桶 2 → 桶 3 → 桶 4。

> 后端 `overview.sites[].active_job_ids` 会把**全局任务**（`site_id = null`）计入每个站点。卡片与排序必须用可用的 `jobs` 列表按 `job.site_id === site.id` 过滤，不能直接用 `active_job_ids.length > 0`，否则全站刮削时所有卡片都会显示「任务中」。后续可让后端拆分 `active_site_job_ids` / `active_global_job_ids`，前端先自行消歧。

#### 5.5.3 筛选与排序控件

- 筛选 chips：`全部 N` / `需关注 N` / `任务中 N` / `已禁用 N`；单选，默认「全部」。
  - 需关注 = 桶 0–3（不含已禁用）。
  - 选中后无结果：显示「没有符合筛选的站点」+「查看全部」。
- 排序下拉：需关注优先（默认）/ 待补全 / 收录量 / 最近刮削 / 名称。
- 排序持久化 `ht-ops-sort`；筛选不持久化（刷新回到「全部」，避免站点“消失”的错觉）。
- 控件高度桌面 32、移动 44；chips 用胶囊，选中态 `--bg-surface` + `--border-hover`，不用绿色填充（绿色只表意）。
- 站点工具条：桌面常显「批量检测 / 批量嗅探 / 导入 / 导出 / 添加站点」；移动端只保留 `+`，其余收进「更多」操作表（复用 `ActionSheet`），避免标题行被五个按钮挤爆。

#### 5.5.4 布局与数量

- 桌面：≥1280 四列，1024–1279 三列，768–1023 两列；移动单列紧凑卡。
- 卡片 min-width 248，min-height 118（桌面）/ 88（移动）；等高对齐，不使用瀑布流。
- 当前实例 21 个站点，CSS Grid 足够，不做虚拟滚动；超过 60 个再评估。
- 整卡可点：`<article>` + 站点名 `<button>` 用 `::after` 铺满；卡内不放任何次级控件，避免嵌套交互。键盘 Tab 到站点名，Enter/Space 打开弹层。
- hover：`--border-hover` + `--bg-surface`；focus-visible 环落在整卡（`:focus-within` 2px `--primary`、offset 2）；不做缩放。

#### 5.5.5 空态

- 无站点：`ServerIcon` + 「还没有采集站」+「添加站点」（主操作）+「批量嗅探」（次操作）。
- 批量检测进行中：工具条按钮显示 `检测中 3/21`，结果写入卡片健康（overview 失效刷新）；不额外维护一次性结果 state。

### 5.6 任务记录（折叠）

- 折叠头：chevron + 「任务记录」+ `进行中 N` chip + 「最近 30 条」+ 右侧最近更新时间；整行可点，`aria-expanded`。
- 默认折叠；**条件自动展开**：页面打开时已有活动任务，或活动任务从 0 变为 >0 时展开一次。用户手动收起后不再自动展开，直到下一个新活动任务出现。
- 展开内容分三组：
  1. **进行中**：复用现有 JobRow（类型 · 站点、状态 chip、触发来源、进度、错误、取消）。活动任务永远置顶。
  2. **手动 / 启动 / 生命周期**：最近 8 条，紧凑行（类型 · 站点、状态、时间、一句结果摘要），不显示取消（非活动）。
  3. **定时**：聚合成一行「定时增量 · N 条 · 成功 x / 部分 y / 失败 z · 最近 HH:mm」，可展开查看最多 10 条明细。定时增量是常规噪音，默认不占 30 行。
- 列表只显示最近 30 条（接口上限），页脚注明「仅显示最近 30 条」。
- 空态：「暂无任务记录，从上方发起刮削、补全或清理」。
- 取消确认沿用现有文案：「确定要取消「X」吗？任务会在当前批次结束后停止。」
- 确认框统一用 `ConfirmDialog`，不再混用 `window.confirm`（全量刮削/清理/取消三处随本次改造统一）。

### 5.7 刮削日志（折叠）

- 折叠头：「刮削日志」+「最近 N 条」+ 最后一条时间；展开时才请求，`staleTime` 60 秒。
- 桌面：沿用现有 9 列表格（时间/站点/分类/页/类型/处理/新增/更新/耗时），`min-width: 720px`，横向滚动。
- 移动：两行制列表——第一行 `时间 · 站点`，第二行 `类型 · 处理/新增/更新 · 耗时`；不做横向滚动。
- 空态：「暂无刮削记录」。加载失败：行内错误 + 重试。
- 本期不做站点筛选；日志是诊断流水，站点维度的问题在弹层「本站任务」里看。

### 5.8 7 天趋势（折叠）

- 折叠头：「7 天趋势」+ 文字摘要 `收录 +N · 补全 +M`（history 首尾差值）+ chevron。
- 展开：现有 SVG 折线图，高度 200（移动 160），两条线 + 面积填充；图例与坐标沿用现有实现。
- 历史 < 2 个快照：「数据积累中，需至少两个历史快照」。
- 不新增请求，跟随 `/crawler/stats` 的 60 秒缓存刷新。

### 5.9 单站弹层

#### 5.9.1 容器

- 桌面：右侧抽屉，宽 520，全高；`--scrim` 遮罩；软投影一层；ESC/遮罩/关闭均可关闭；关闭后焦点回到卡片。
- 移动：`BottomSheet`（已有焦点陷阱与下滑关闭）；现有默认 max-height 60vh 放不下任务与探测历史，需增加 `tall` 可选属性（max-height 90vh），内部滚动。
- 标题：站点名 18/600 + 健康 chip（沿用现有抽屉；工具型浮层不套 24px 弹窗标题）；下方 `base_url` 12/muted、单行省略、`title` 全文。

#### 5.9.2 内容分区（自上而下）

1. **健康**：两行定义列表——最新探测（正常/异常/无记录 + 延迟或错误）、24h 可用率。自动禁用时插一条警示条（`auto_disabled_at`，沿用现有黄色提示样式）。
2. **数据**：`已收录` / `已补全` / `未补全` / `补全率` 四项，2×2 栅格或四行，数字 tabular。
3. **操作**：两列按钮网格
   - 增量刮削（`crawl.incremental`）
   - 单站补全（`detail.fill` + site_id）
   - 立即探测（`probeSite`，探测后刷新健康）
   - 编辑（切换为名称/地址输入 + 保存/取消）
   - 禁用站点 / 启用站点（乐观更新 + 刷新 overview）
   - 主次：有未补全时「单站补全」为主操作；否则「增量刮削」为主操作；站点禁用时「启用站点」为主操作。其余为描边按钮。
4. **本站任务**：最近 5 条（类型、状态、进度、时间），活动任务带取消；空态「暂无任务记录」。
5. **探测历史**：最近 10 条（时间、正常/异常、延迟/错误；接口最多返回 50 条，界面先展示 10 条）；空态「暂无探测记录」。
6. **危险区**：分隔线 +「删除站点」红描边，置于弹层最底部，避免与高频操作相邻。

#### 5.9.3 操作状态矩阵

| 操作 | 禁用条件 | 进行中文案 | 成功后 |
|---|---|---|---|
| 增量刮削 | 本站有活动 `crawl.incremental`；站点已禁用；`startingKind` 同类型 | 刮削中… | 卡片出现任务 chip，任务记录计数 +1 |
| 单站补全 | 有活动 `detail.fill`（全局去重）；站点已禁用 | 补全中… | 同上 |
| 立即探测 | 探测中 | 探测中… | 刷新健康与卡片 |
| 启用/禁用 | 提交中 | — | 乐观更新，失败回滚并 toast |
| 删除 | 本站有活动任务；删除中 | 删除中… | 等 SSE `site_delete_progress` 完成后关闭弹层并 toast |
| 编辑 | 编辑中 | — | 保存后刷新卡片与弹层标题 |

- 站点已禁用时，增量/补全禁用并显示提示「站点已禁用，启用后可操作」。
- 探测会写健康日志但不改变自动禁用计数（沿用现状）。
- 删除必须二次确认；失败恢复按钮并 toast。

#### 5.9.4 数据来源

- 弹层打开时不重复拉全量：站点行、健康、统计数字由页面传入；仅调用一次 `getSiteHealth(id)` 获取 24h 可用率与探测历史。
- 本站任务从页面已加载的 `jobs` 中过滤 `site_id`；若后续需要更久历史，再加 `/maintenance/jobs?site_id=`。
- 编辑保存后调用 `updateSite`，随后刷新站点列表与 overview。

## 7. 状态与交互

### 7.1 加载 / 空 / 错误

| 区块 | 加载 | 空 | 错误 |
|---|---|---|---|
| 概览条 | 4 条骨架 | 不适用 | 「统计加载失败」+ 重试 |
| 卡片墙 | 8 张骨架卡 | 无站点空态（见 5.5.5） | 「站点状态加载失败」+ 重试；卡片区不整页报错 |
| 任务记录 | 3 行骨架 | 「暂无任务记录…」 | 折叠头显示「加载失败」，展开后重试 |
| 刮削日志 | 展开后骨架 | 「暂无刮削记录」 | 行内错误 + 重试 |
| 弹层健康 | 2 行骨架 | 「暂无探测记录」 | 错误行 + 立即探测 |
| 趋势 | 展开后骨架 | 「数据积累中…」 | 静默隐藏图，保留摘要 |

四个请求互相独立：任一失败不影响其他区块渲染（`useQuery` 各自 error）。

### 7.2 并发与刷新

- 不新增轮询：jobs 仅在活动任务存在时 2 秒轮询；overview `staleTime 30s`；stats 60 秒 localStorage 缓存。
- SSE `maintenance_progress` 只作为失效信号，真实状态以快照为准（沿用 `useMaintenance`）。
- 删除站点走 `site_delete_progress` SSE，完成后移除卡片；失败恢复并 toast。
- 批量检测 NDJSON 流在离开页面时 abort（沿用现有 `AbortController`）。
- 新增站点/导入/批量嗅探完成后，失效 `sites` 与 `overview` 两个查询；批量检测完成后只失效 `overview`。

### 7.3 折叠与持久化

- 三个折叠区状态只在组件内保存，不持久化；进入页面默认折叠。
- 任务记录在活动任务出现时自动展开一次；用户手动收起后尊重用户选择。
- 排序持久化；筛选、折叠不持久化。

### 7.4 提示与确认

- 成功/失败提示沿用 `toast`（同消息 4 秒去重、最多 3 条）。
- 全量刮削、清理、取消任务、删除站点、导入站点使用 `ConfirmDialog`；文案沿用现有（全量 20–40 分钟、清理约 1 小时、取消当前批次结束停止）。
- 批量检测使用现有 `ConfirmDialog`，不再用 `window.confirm`。

### 7.5 动效

- 折叠：高度 + 透明度 200ms；尊重 `prefers-reduced-motion`（直接切换）。
- 弹层：抽屉 200ms 滑入；底部弹层沿用现有手势与动画。
- 卡片 hover 只改边框与表面色，不做位移/缩放。

## 11. 验收条件（Given / When / Then）

1. **默认视图**
   Given 用户进入 `/ops`
   Then 看到概览条、全局操作、活动任务（若有）、站点卡片；任务记录、刮削日志、趋势默认折叠。
2. **折叠状态**
   Given 无活动任务
   When 展开/收起任务记录与日志
   Then 状态正确切换且不触发额外轮询；日志仅在展开时请求。
3. **活动任务**
   Given 启动全量刮削
   Then 全局按钮进入进行中状态；活动任务条出现并可取消；任务记录自动展开并置顶该任务；取消后回到终态。
4. **站点排序**
   Given 站点列表同时包含异常、已禁用、待补全与正常站点
   Then 默认异常/任务中/待补全在前，已禁用沉底；切换排序与筛选立即生效；刷新后排序保留、筛选回到全部。
5. **卡片打开弹层**
   Given 点击任一站点卡
   Then 打开弹层，显示健康、数据、本站任务、探测历史；不再发起重复的全量站点请求。
6. **单站增量**
   Given 弹层内点击「增量刮削」
   Then 提交 `crawl.incremental`，卡片显示任务中，任务记录计数 +1；重复点击不会重复提交。
7. **单站补全**
   Given 站点有待补全且无全站补全任务
   Then 可启动单站 `detail.fill`；全站补全运行中时按钮禁用并说明原因。
8. **探测**
   Given 点击「立即探测」
   Then 探测完成后健康与卡片刷新；探测历史新增一条；不改变自动禁用计数。
9. **删除**
   Given 本站无活动任务，点击删除并确认
   Then 按钮显示删除中；SSE 完成后卡片消失并提示；失败恢复卡片并提示。
10. **批量操作**
    Given 点击批量检测
    Then 工具条显示逐站进度；完成后卡片健康更新；离开页面中止流。
11. **设置迁移**
    Given 访问 `/settings?tab=sites` 或 `?tab=logs`
    Then 重定向到 `/ops`；设置页只剩分类设置与下载设置，默认分类设置。
12. **移动端**
    Given 390px 视口
    Then 站点为单列紧凑卡；弹层为整屏底部弹层；所有操作 ≥44px；底部导航显示「运维」。
13. **主题**
    Given 深色/浅色主题切换
    Then 卡片、进度、状态 chip 均使用语义变量；正文对比度 ≥4.5:1；状态不单靠颜色。
14. **空态**
    Given 无站点 / 无任务 / 无日志
    Then 对应区块显示空态文案与下一步操作，不出现空白区块。
15. **性能**
    Given 进入 `/ops`
    Then 首屏请求不超过 4 个（sites、stats、jobs、overview），无额外全量查询；活动任务存在时才 2 秒轮询。
